# Security Policy

This repository is a public research-software project rather than a hosted service, but security and responsible disclosure still matter.

## Reporting A Security Issue

If you discover a security-sensitive issue:

- do not publish exploit details in a public issue
- open a minimal GitHub issue requesting a private reporting path, without sensitive details
- describe the affected file, interface, or dependency at a high level only

## Scope

Security concerns may include:

- accidental exposure of secrets or credentials
- unsafe handling of local paths or file writes
- dependency issues with clear security relevance

General workflow bugs, scientific disagreements, and calibration problems should go through the normal issue process instead.
